# Problems and instances

Vamos pegar um exemplo de multiplicação de 981 by 1234. Os algoritmos não só poveem uma forma de gerar a multiplicação para esses dois particulares níumeros. Em fato, eles dão a solução geral para o problema de multiplicar dois números positivos

- Nós dizemos que (981, 1234) é uma instância desse problema

Multiplicar 789 por 9742, que nós podemos também expressar por (789, 9742) é outra instância do problema de multiplicação

<note>
Os problemas mais interessantes possuem coleções infinitas de instâncias
</note>

Um algoritmo deve funcionar corretamente nas varias instâncias do problema para dizermos que ele soluciona o problema. Para demostrar que um algoritmo é incorreto, nós precisamos somente encontrar uma instância do problema que o algoritmo não resolve. 

Assim. temos dificuldade de provar o teorema, isso usualmente faz com que temos dificuldade de provar o quanto um algoritmo está correto

Para isso ser possivel devemos a nos atentar quando especificarmos um problema é importante definir o _domain of definition_, isso é o conjunto de instâncias a ser considerado

<note>

Temos que ter esse domain of definition já que não podemos trabalhar com a ideia de todas as instâncias pois nossas maquinas tem um processamento e memoria finita, ainda mais em alguns dispositivos

</note>
